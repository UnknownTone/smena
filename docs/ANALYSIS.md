## Методика

1. **Покадровые признаки** (`tools/analysis/features.py`): 44.1 кГц, окно 2048, шаг 512 (~86 кадров/с).
   RMS, пик, энергии полос (sub 20–60, bass 60–150, lowmid 150–500, mid 0.5–2k, himid 2–6k, high 6–16k),
   центроид, rolloff, плоскостность, спектральный поток (общий и по полосам), стерео S/M, хрома (12),
   доля ударного (HPSS на 96 лог-полосах: медиана по времени / по частоте).
2. **Темп** (`tempo.py`, `tempo2.py`, `tempo3.py`): автокорреляция огибающей атак по разным полосам;
   финальная проверка — гребёнка по 64 долям с шагом 0.05 BPM и робастный z-балл пика.
3. **Значимые изменения** (`changes.py`): признаки агрегируются по тактам (для треков без сетки — по 2 с).
   Изменение значимо, если одновременно:
   - t-тест Уэлча 8 тактов до / 8 после: p < 0.01 с поправкой Бонферрони на число позиций в треке;
   - эффект Коэна |d| > 2;
   - величина изменения выше порога слышимости (1.5 дБ для полос, 0.15 октавы для центроида и т.д.).
   Пики разрежены минимум на 8 тактов.
4. **Второй проход** (`pass2.py`): смена гармонии (косинусное расстояние хромы, робастный z > 5);
   «смена части» = значимая смена ≥ 3 разных признаков в пределах ±1 такта; акценты относительно
   локального фона (4 с: > 6 MAD и > 99-го перцентиля трека); выравнивание смен по фразам (тест Рэлея).
5. **Третий проход** (`pass3.py`): изменения ясности пульса (окна 8 с), хронология провалов и акцентов.

Все события с временами — `data/analysis/events.json` (ключ `results` → параметр → трек → список событий
`{bar, t (сек), delta, d, p}`). Обзорные графики признаков — `data/analysis/overview_1..4.png`.

## Главные выводы

1. **Темп есть только у двух треков:**

   | Трек | Темп | Надёжность | 16 тактов |
   |---|---|---|---|
   | 1 | нет сетки (свободное время) | z ≈ 6, разные значения | — |
   | 2 | **139.6 BPM** (модуляции 3/4, 3/8) | z = 91 | 27.5 с |
   | 3 | **120.2 BPM** (триольные 80/160) | z = 126 | 31.9 с |
   | 4 | нет сетки | z ≈ 6.6 | — |

2. **Громкость почти неподвижна** — альбом плотно сведён и компрессирован. Драматургия — в тембре:
   бас, яркость, шумность, стерео, доля ударного.
3. **Смены не выровнены по фразам**: в треках 2 и 3 значимые смены приходятся на любое место фразы
   (Рэлей p > 0.3 для mod 4/8/16).
4. Классических нарастаний и дропов почти нет (4 случая, все во вступлениях/концовках).

## Особенности треков

- **1**: стена звука почти без изменений до 7:20; 7:20–8:02 — серия обрывов, смена гармонии, рост шумности (кульминация).
- **2**: самый ритмичный в басу; бит появляется/исчезает ~0:54/1:08 и ~3:52/4:06; сильнейшая смена гармонии альбома — 5:36 (z = 25).
- **3**: самый насыщенный событиями (12 смен частей); 0:52 входит бит; 5:47 — суббас +37 дБ одновременно со сменой гармонии и доли ударного.
- **4**: обрывы во вступлении (0:03–0:19) и концовке (5:41–5:50); смены гармонии 4:24 и 4:56.

## Как воспроизвести

```bash
cd tools/analysis
python features.py "ПУТЬ/К/ПАПКЕ/С/ТРЕКАМИ"
python tempo.py
python changes.py
python pass2.py
python pass3.py
python overview.py
```

- Рабочие файлы (≈ 100+ МБ `.npz`) пишутся в `data/analysis/work/` или в папку из переменной `PHOTOVJ_WORK`.
- Нужны: Python 3.12+, numpy, pygame-ce (для декодирования mp3/flac). scipy не нужен.
- Треки в папке должны начинаться с номера: `1. Name.flac`, `2. Name.mp3`. `features.py` берёт по одному файлу
  на номер и **предпочитает FLAC**. Исходный анализ шёл по 1 FLAC + 3 MP3; повторный прогон на FLAC даёт те же
  25 из 27 параметров и отличия ±1–4 события только у покадровых детекторов (акценты, провалы).
- Темп треков для разбиения на такты задан в `changes.py` (`TEMPO = {"1": None, "2": 139.6, "3": 120.2, "4": None}`) —
  для другого альбома его нужно выставить по результатам `tempo3.py`.
- `make_xlsx.py` — генератор исходной xlsx без openpyxl; `read_xlsx.py` — чтение xlsx (включая комментарии) без openpyxl.
